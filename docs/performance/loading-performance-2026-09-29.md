# Loading performance implementation

## Scope and evidence

The implementation follows the measured P01 through P11 audit at source revision `a32b5102f211dd5953b6fb35ac198ceaa95af434`. Three GPT 6.1 Sol agents implemented separate client dependencies, public access/styles/session, and Firestore activity responsibilities. No production data or credentials were modified. Existing CI built and deployed the PR preview; its production deployment step was skipped.

The anonymous access page now renders useful content without loading the campus dependency tree or requesting `/api/auth/me`. Cookie presence only selects the private `/campus` server route; the existing server session validator remains authoritative. Personalized HTML, RSC and authentication responses use `private, no-store`. The service worker precaches the public shell without credentials and rejects personalized responses.

Private responses also append `Vary: *`: the original worker fetch handler persisted successful responses despite `Cache-Control: private, no-store`. A native Chromium Cache API fixture executing that original handler stored the private payload with `Vary: Cookie`, and rejected its write with `TypeError` and no cached entry when the response used `Vary: Cookie, *`. The response remained readable in both cases. This implements the [Service Workers Cache.put requirement](https://www.w3.org/TR/service-workers/#cache-put). The fixture used no service worker registration, sessions or provider access; the repository search did not establish whether any deployed clients still have that worker registered.

The installed OpenNext response adapter gives middleware headers precedence over Next's response headers. A real adapter test reproduced the loss of Next's RSC/router negotiation fields when the proxy supplied only `Vary: Cookie`. The proxy now preserves those four fields as well as Cookie and the private wildcard. The explicit field list matches installed Next 16.3.5, Cloudflare adapter 1.20.6 and OpenNext AWS 4.1.4 and must be reviewed on upgrades. The installed routing pipeline executes middleware before resolving the rewritten route and its optional cache; this code inspection found no private route bypass, but does not replace a real Worker HTTP check.

Native `next start` has a different final header boundary: `next/dist/build/templates/app-page-runtime.js` unconditionally replaces `Vary` with the route module's React negotiation fields after middleware. The production preflight reproduced the loss of Cookie and the wildcard while retaining `private, no-store`. The new local API contract's original Cookie expectation therefore assumed Worker behavior on the native server. The corrected native contract checks case insensitive RSC variation, HTML and Flight identity for both accounts, private/no-store and absence of those identities from the anonymous page. The real OpenNext adapter contract retains Cookie, all React negotiation fields and the private wildcard. No protected assertion was changed for this correction, and native Next alone does not establish legacy offline cache protection or Worker headers.

## Activity rollout

1. Deploy the new Firestore rules and `projectCoursePostActivity` trigger to dedicated staging.
2. Run `scripts/backfill-course-activity.mjs` against the explicitly confirmed staging project/database. Dry runs always inspect from the beginning; only incomplete write runs resume a checkpoint. The default checkpoints are separate for dry and write modes.
3. Verify a complete dry run reports no differences, including archived sections, empty sources, stale projections, imported posts, edits and deletions. Repeat after completion to detect new drift.
4. Verify student, teacher and revoked membership access through real staging identities, with all client writes denied.
5. Enable `NEXT_PUBLIC_CEOUBB_ACTIVITY_PROJECTION=enabled` in a new web build only after the staging checks succeed. Repeat the guarded process for production deployment. Rollback is the disabled gate with the existing full post reader.

No provider rollout or backfill was executed by this task. The compact schema reduces eligible document fields, but its actual transfer/latency benefit is not measured against real Firestore snapshots. Projection writes and reads add provider work and cost.

## External limitations

The local Windows OpenNext build passed Next and the public cache guard, then failed with `EPERM` while creating an `import-in-the-middle` symlink. Linux CI subsequently completed packaging and deployed the preview. No operating system security settings or dependencies were changed to bypass the Windows restriction. Real authenticated Worker identity separation and older service worker updates on devices remain unverified.

Real Google OAuth, Turnstile, email/FCM delivery, provider geography, real device responsiveness and carrier performance are unverified. Dedicated staging credentials `QA_STAGING_EMAIL`, `QA_STAGING_PASSWORD`, and `QA_STAGING_API_KEY` were not configured. Production credentials were not copied into the isolated runtime. A public staging response is not proof of the private campus.

Before production promotion, verify authenticated HTML/RSC identity separation with dedicated institutional staging accounts and actual older service worker updates; collect field INP and private SQL/snapshot readiness. Repeat the measured Lighthouse procedure on the production release and physical target devices. Compiler or database placement changes require that evidence first.
