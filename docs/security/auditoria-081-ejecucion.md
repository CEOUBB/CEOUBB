## Semántica y límites operativos

- El cierre remoto cierra **todas** las sesiones, incluida la actual. Firebase no ofrece una sesión web por dispositivo que las reglas actuales puedan revocar aisladamente. La interfaz lo informa antes de pulsar.
- Si falla Google/Turso durante la revocación no se devuelve éxito. El corte Firebase se conserva; la fila relacional se mantiene hasta completar el borrado, para poder reintentar. Un fallo distribuido necesita reconciliación, no revertir la lápida de seguridad.
- La invalidación de enlaces históricos recorre la sección completa. Puede tardar en cursos con muchos archivos; un conflicto o timeout exige repetir la operación. No cambia ni borra bytes. Las descargas oficiales nuevas no emiten tokens permanentes. Los enlaces de terceros a esos archivos dejan de funcionar tras revocar; las copias previamente descargadas no se pueden retirar.
- `getBlob` necesita CORS del bucket para el origen web. Capacitor guarda el blob en su caché y usa el visor existente. Los tamaños siguen acotados a 50 MiB para material y 25 MiB para entregas; queda pendiente comprobar memoria y visor en hardware físico.
- Las entregas históricas siguen siendo legibles con matrícula; escribir una reentrega exige el contrato nuevo. Un ID ocupado incorrectamente antes del despliegue requiere reparación administrativa caso por caso; las reglas no reasignan documentos ajenos.
- La prueba SQLite usa un archivo temporal porque el driver abre otra conexión al iniciar una transacción. En Windows sus handles de transacción permanecen hasta salir del proceso; el archivo queda en el directorio temporal del sistema.
